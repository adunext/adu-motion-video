## 独立上手测试带来的修正

首次测试发现 `doctor` 与导出器可能挑选不同浏览器，现已统一查找顺序；手绘示例补上 `?t=秒数` 静帧入口；README 增加了“直接导入自己的口播”和“接入自己的手绘旁白”的完整请求示例。浏览器入口与静帧查询在修正后另外检查。

## 没有由这些测试证明的事情

- Linux / WSL / Windows 的完整兼容性尚未实测；原生 Windows Shell 不是当前说明的执行路径。
- 合成音轨与静音手绘例子不能证明任意真实口播的逐帧口型精度，也不验证自动转写或声音克隆。
- 人脸追踪依赖 macOS，本轮没有重新验证其精度。
- 大型历史场景片段已做语法与引用检查，但没有把缺少媒体的全部配方重新做成长片。
- 创意质量仍取决于文案、素材、动作编排与审片；代码可运行不等于每条片子无需修改即可发布。

## 你可以怎样复核

按 README 从 `doctor`、`setup` 开始，运行 `demo` 和手绘示例命令，再运行：

```bash
bash "$SKILL_DIR/scripts/pipeline.sh" check "/你的输出目录/my-first-demo/demo.mp4"
bash "$SKILL_DIR/scripts/pipeline.sh" check "/你的输出目录/handdrawn-demo.mp4"
```

前者应为1080帧/18秒/60fps且有音频，后者应为480帧/8秒/60fps且无音频。实际工程的验收始终以自己的素材和最终文件为准。
