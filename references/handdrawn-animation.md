# 手绘叙事：接续动作与可靠导出

适用：在已有手绘动画里补一段动作、延长一句口播，或制作带角色和道具的叙事动画。先保留原工程的笔触、镜头、角色模型和渲染器，再扩展动作。仅替换台词或新增一张说明卡，不能解决动作接续。

## 先跑一个不需要素材的例子

[handdrawn-continuity.html](../examples/handdrawn-continuity.html) 是 **8 秒、1920×1080、60fps** 的独立教学动画：角色收拢散页、用力攥紧、捧出成果卡、慢慢停稳。下载后用现代浏览器打开，点击画面或按空格播放。没有配音；画上的文字是动作说明，不是语音识别结果。

它是本仓库原创的 **Canvas2D 示例**，不依赖 p5、WebGL、图片、第三方字体或网络。它演示连续动作和时间契约；已有 p5.brush 工程应继续使用原笔刷与合成管线。字体使用系统中文字体，跨平台的字形和像素结果可能不同。

安装运行环境后，在终端将 `SKILL_DIR` 设为实际 skill 目录（安装见仓库 README），从任意可写输出目录执行：

```bash
node "$SKILL_DIR/scripts/render_project.mjs" \
  "$SKILL_DIR/examples/handdrawn-continuity.html" --probe

node "$SKILL_DIR/scripts/render_project.mjs" \
  "$SKILL_DIR/examples/handdrawn-continuity.html" \
  --stills-dir "handdrawn-frames-v1" --times 0,2.8,4.4,5.3,7.5

node "$SKILL_DIR/scripts/render_project.mjs" \
  "$SKILL_DIR/examples/handdrawn-continuity.html" \
  --output "handdrawn-demo-v1.mp4" --fps 60 --width 1920 --height 1080
```

输出目标必须不存在；这个例子应得到 **480 帧、8 秒、无声** 的 MP4。没有 Playwright 或 Chromium 时先完成 README 的环境安装，不应把缺依赖说成动画故障。已有自定义安装可加 `--playwright-module 路径`、`--browser 路径`。

修改入口：文件顶部的 `C` 是色板，`phase` 是分段文字和起止点，`hero()` 是角色及手部锚点，`papers` 是原有道具位置。`window.renderAt(t)` 接受秒，`window.END` 和 `window.READY` 供本仓库导出器读取。预览播放不会改变离线导出状态。

## 从上一镜延伸，而不是重新摆场

先抽出插入点前后几帧，记录四组连续性锚点：角色脚底/肩膀/双手，道具位置与朝向，镜头缩放与偏移，背景和字幕区域。继承上一镜最后的姿态，不要让人物先回到默认站姿。

| 阶段 | 主动作 | 次级动作 | 检查点 |
| --- | --- | --- | --- |
| 起势 | 从原来的手臂和身体姿态伸手 | 视线先到目标、肩膀稍跟随 | 插入前后角色位置、比例一致 |
| 收拢与压缩 | 已有纸张沿短弧线汇到同一双手 | 纸张略错峰，身体微压缩 | 纸张不凭空消失，手和道具接触 |
| 释放 | 从压缩位置弹出小成果卡 | 表情舒展，少量光点强调 | 同一位置完成形态转换 |
| 收势 | 卡片、手、表情依次停稳 | 配角晚一点反应 | 保留读字时间，接回后镜 |

口播很短时，可将这些阶段压到约 1.2 秒：准备 0–0.24、汇聚/压缩 0.24–0.67、结果 0.67–0.91、停稳 0.91–1.20。**这是调参起点，不是固定节奏**；最终按实际语音的重音安排。教学示例放慢到 8 秒，便于看清结构。

让主动作只有一个重心。纸张汇聚、手收紧、卡片出现之间有因果；配角、闪光和文字不同时抢镜。避免直接把人物换成全屏卡片而丢失用户要求的原有动画。

## 先确认引擎契约

| 需查看 | DOM/CSS/SVG 工程 | p5.brush / Canvas 工程 |
| --- | --- | --- |
| 主输出 | 固定尺寸舞台元素 | 实际输出 canvas，可能另有 WebGL 中间画布 |
| 渲染入口 | 常见 `renderAt(t)` 更新 DOM | 可能还需要 `preFrame`、`redraw`、字层、纸纹和字幕合成 |
| 就绪 | `READY`、字体和图片解码 | p5 初始化、笔刷/字体/纹理、视频序列就绪 |
| 导出 | 本仓库严格截图导出 | 沿用该工程的 canvas 导出适配器，并检查实际 canvas 像素尺寸 |

不要因为浏览器都能打开，就把两种运行时函数混用。预览 CSS 缩放后的窗口尺寸也不等于最终画布尺寸。先取一帧确认引擎的输入、输出、就绪信号，再开始长片。

已有引擎提供场景回调时，局部插入优先复用它。以下是**需要按工程改名的适配示意**，不是能直接复制运行的通用脚本：

```js
const renderOriginal = window.renderAt;
window.renderAt = async (outputTime, ...args) => {
  window.OUTPUT_T = outputTime; // 字幕读取最终成片时间
  const m = mapOutput(outputTime);
  if (!m.insert) return renderOriginal(m.sourceTime, ...args);

  const previousLoop = window.LOOP;
  window.LOOP = () => drawExtension(m.localTime);
  try {
    return await renderOriginal(m.anchorTime + m.localTime, ...args);
  } finally {
    window.LOOP = previousLoop;
  }
};
```

`drawExtension()` 复用前镜的绘制函数、人物参数和坐标，让起势从原姿态开始。所有分支仍经过原引擎的绘图、字层、纸纹和字幕合成；不要另复制一份核心渲染器。`finally` 防止渲染异常或倒退取帧后，下一镜仍调用插入回调。一个页面内逐帧串行渲染；并行工作应使用独立页面，避免全局回调互相覆盖。

## 三个时钟分别管理

用整数帧记录剪辑表，然后在渲染边界换算为秒。约定插入区间为 `[start, end)`，让边界帧只属于一个区间。

- **输出时钟**：字幕、最终音乐/音效、交付时间码使用它。
- **原工程时钟**：未改动的场景和原素材仍按旧时间运行；插入之后从相同原帧接回。
- **插入局部时钟**：新动作从 0 开始。视频素材按自身帧率取帧；补录音频独立保留完整时长。

例如 60fps 原片在第 900 帧前插入 72 帧：输出 `[900,972)` 是新增内容；输出第 972 帧对应原第 900 帧。原片 N 帧，最终恰好 N+72 帧。新增多段时，按原片帧位置排序，累加之前的插入长度。

字幕不仅要平移 `t0/t1`，逐字开始/结束、高亮和停留时间也要更新。跨插入点的原句要按实际口播拆分，避免重复说词、旧字幕悬在新镜头上。开始点恰在切口的内容归切口之后，结束点恰在切口的内容归切口之前。

48kHz 音频在 60fps 下每帧恰好 800 个采样；新增 72 帧对应 57,600 个采样。拼接后核对音频采样总数和画面帧总数，短淡化只改变音量，不偷偷缩短时长。只改动作且时间不变，可以沿用已验证的混音；改了时序就必须重新定位语音、配乐与音效。

## 手绘质感与字幕留位

- 每帧由绝对时间计算位置、缩放、表情、透明度和可见性；重复/倒退到同一时间，应得到同一画面。
- 笔触扰动用固定种子和 `Math.floor(t * 12)` 等有限频率，主运动仍按 60fps 计算。不要让每帧调用无种子的随机数导致镜头抖动。
- 让压缩、弹出和衰减用不同曲线。弹性用于一个重点道具，其它元素轻一点。
- 在设计阶段画出字幕安全区；道具停在字幕上方，人物手部不与文字重叠。长英文必须另看一帧。教学示例底部是解释性图例，接真实口播时要替换成适合该画幅的字幕区域。
- 从实拍插入改回动画时，检查是否遗留“实拍专用”的字幕位移。字幕坐标必须和当前布局一致。

## 插入素材与长片故障

图片序列先检查首尾。部分手机裁剪片的最后数帧可能全黑；不能用音频正常来推断画面正常。确认黑帧确属素材尾部后，可保持最后一个有效画面至该片结束，保留完整语音并记录这个修复。取帧上下界都必须明确：

```js
const index = Math.min(lastValidFrame,
  Math.max(1, Math.floor(localSeconds * clipFps + 1e-6) + 1));
```

若中间有缺帧或文件读取失败，应停止并定位；不要将所有错误都替换成最后一帧，也不要无限重试。

p5/WebGL 长时间运行曾出现浏览器调用超时。先检查资源占用和出错帧，必要时将导出分为每批不超过 10 秒，**每批新开并关闭整个浏览器进程**，全局帧号连续；不能只换一个标签页后称为重启。示例参数是 60fps × 10 秒 = 600 帧/批，按目标机器实际情况调整。每批设置明确超时，失败仅在有新证据时有限重跑，不能静默拼接历史帧。Canvas2D 示例不需要默认采用这套重启策略。

WebGL 警告不自动等于可忽略。先复现、查看受影响帧，只有已确认无视觉影响的具体警告可记录后放行；页面异常、缺素材、字体/图片解码失败仍应停止。

## 验证后再说“可用”

1. 看动作前、起势、压缩、成果、收势、接回后镜，至少各一帧。
2. 导出覆盖前后衔接的短片，检查接触关系、移动轨迹、字幕位置、音画重音。
3. 随机跳转、倒退和重载后取同一时刻，比较画面；固定同一浏览器与字体环境。
4. 完整导出后数帧、核对宽高/帧率/音视频时长，并完整解码。源文件和混音可记录 SHA-256，证明导出期间未变。
5. 区分实际验证范围：静帧通过、短片通过、完整导出通过是不同结论；无声教学示例不能证明真实口播对齐。保留原版，使用新版本文件名，交付可编辑工程与简短说明。

本条目提炼的是手绘工程中已用过的接续方法；公开示例不包含原作者的私人视频、口播、人物素材或旧选题。它能验证绘图入口和连续动作，用户的每个新项目仍需要上述声音、资源和成片检查。
