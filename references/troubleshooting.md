# 踩过的坑

## 口型
- **症状**：前半段口型对得上，后半段慢 1–2 帧。**原因**：分段渲染的起止时间没落在整帧上。**解决**：render.mjs 用整数帧索引 `(f0+i)/fps`；pipeline 的分段按 `round(END*60*i/K)` 帧切。
- **症状**：所有段都慢 2–3 帧（约 40ms）。**原因**：用 stream start_time 当音画偏移。**解决**：align_talk.py 用画面逐帧比对来求每段的视频偏移。
- **症状**：某一段对不上。看 align_talk 输出的 median r：低于 0.85 通常是这段口播用了别的原片，或者剪辑时加了变速。先用 `--speed` 固定倍速重跑，再检查 `--raw` 是否漏了某段原片。
- 30fps 原片放到 60fps 输出时，相邻两帧通常共用一张原图；这不等于允许固定音画偏移。检查原图取帧与声音主时钟，再区分采样分辨率和真实漂移。

## 渲染
- **`-shortest` 会截掉结尾**：mix.wav 比视频短几十毫秒就会少 2 帧。先确定准确输出帧数和音轨尾部策略；确需静音补尾时才用 `-af apad -t <END>`，不要掩盖缺失的旁白或音效。
- **Chrome 截图在大量图片时变慢**：精灵图（4×4 一张）比 16 张单独的图快很多；大规模作品墙可采用此法。
- **数据文件缺失报 ERR_FILE_NOT_FOUND**：严格导出默认失败。先确认当前场景是否需要该文件；只有真正可选的数据才可通过 `--optional-data` 显式声明，不能把缺失真人、字幕或作品墙当作正常。
- **分段通过，拼接后帧率不符**：先看错误里的 expected/actual 和每段时钟字段，不直接放宽验证。严格导出按累计整数帧边界声明拼接时长，分别将 PTS/DTS 对齐输出帧时钟，保留 B 帧显示顺序，并设置一致的 MP4 track timebase。不能将 PTS 与 DTS 都替换为包序号；那会弄错 B 帧的显示顺序。
- **圆形转场在旧画面上留下一个白点**：main.js 里圆刚出现时透明度要是 0（`Math.min(1-q, clamp(p*25))`）。
- **ffmpeg 没有 drawtext/subtitles**：所有文字都在 HTML 里画。

## 布局
- 横屏默认字幕区 y 870–1040（其它尺寸重新排版）：大卡片缩到 .9 并上移到 y 505，九宫格和窗口也要缩小。
- 缩放的元素在"弹入"时可能会扫过口播卡片：把放大倍数调小（1.0–1.3），或者把标题放在左半屏。
- 在 `show()` 之后又用 `place()` 改缩放会覆盖 show 的效果：要缩放就用 show 的 `s` 参数。

## 其他
- 生成 GitHub 网页截图、下载素材时，用户要求"全部"就要检查数量是否有更新；数量只代表本次抓取时的状态。
- 事实类内容（发布日期、持股比例、显存）不确定时标"待核实"，不要编造。

## 方形人物窗切掉嘴部

新人物在竖屏原片中的位置可能与旧素材不同。完整卡片包的 `s06` 已按新口播跟踪裁切；重建工程时读取新 `face.js`，使用目标时钟。不要把某个旧项目的 `object-position:50% 28%` 或这次临时调整的百分比复制成通用默认。非 macOS 可显式提供审核过的固定人脸框；方形、圆形和竖长人物卡分别抽帧确认。

## 总帧数正确但接缝有跳动

平均帧率和首尾时长不能排除中间时间戳跳变。`render` 现在对最终文件的每一帧检查显示时间是否等于 `帧序号 / fps`，再完整解码；结果写在导出清单的 `frame_clock`。这是编码连续性检查，不代替动画的视觉流畅度或声音验收。
