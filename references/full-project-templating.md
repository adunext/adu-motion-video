# 复用完整动画工程：从新文案到新成片

## 这套功能的范围

目录中的十种当前风格、32 个完整组已新增原生竖屏候选版本。需要竖屏时按目录的 portraitSelection 选版本，在 brief / spec 顶层设置 `"layout":"portrait"`，其余媒体、动作与音频流程相同；导出自动读取工程画幅。详见[竖屏契约与实际检查范围](portrait.md)。下文的旧源包说明不自动获得此能力。

先运行 `bash "$PL" packs` 动态发现包，按语义和显式版本读取各包清单。目前稳定的 `classic-performance@1.0.0` 有三个完整叙事镜头组，`continuous-performance@1.0.0` 有两个，`paper-balance@1.0.0` 有一个试点外来源续接组；B 的计划干扰组仍只在候选中。它们没有提炼原工程的全部场景，稳定范围限于清单内的组，既有验收记录使用 macOS 1080p60；跨平台接入见[兼容说明](compatibility.md#平台与助手接入)。精确的新内容证据、环境和限制见[能力矩阵](../docs/capability-matrix.md)。下述 `anim3/anim4` 说明仍适用于旧完整宏场景包。

`packs/anim3` 与 `packs/anim4` 保存的是两份 HTML/CSS/JavaScript 原工程的**完整宏场景**，分别有 12 场和 9 场。场景内的对象运动、镜头、转场、多阶段状态与 `S()` 音效编舞仍在源代码里。`manifest.json` 把场景语义、源时间、动作节点、受保护的动作窗口、可替换的文字/数字/媒体槽列成接口。`audio_timeline.json` 记录原配乐结构，供新时间轴重排。

这与 9 个基础 `TPL` 的关系是“完整工程包”与“快速起步组件”，不是 21 场被归并成 9 种静态卡片。新文案可挑选、重排或重复宏场景；选中的每一场都是新的实例，有独立文字、数值、媒体和时间绑定。**不能承诺任意文案自动无损复刻**：语义不合、缺素材、动作窗装不进目标片长或镜头布局容不下新文字时，需要改分镜或继续设计。这两份旧完整包的状态为 **experimental**，完整新口播导出与原工程逐镜对照的最终验收尚未宣称完成。

| 工程包 | 场景内容 | 入口 |
| --- | --- | --- |
| `anim3` | 连续编辑卡片、人物道具、网络关系、软件演示、总结等 12 场 | [场景清单与素材说明](../packs/anim3/README.md) |
| `anim4` | 作品墙、九宫格、审片报告、软件窗口、赛道与结尾等 9 场 | [场景清单与素材准备](../packs/anim4/README.md) |

包名只是工程 ID，不应变成对外视频题目、账号名或风格名。其他历史工程（包括[手绘卡通叙事](handdrawn-animation.md)）已有复用经验，但还没有按这个契约提取成完整包。

## 来源与多包编排

用户指定某个模板或刚提炼的工程包时，先把它作为本期动画来源。输入目录中的口播、SRT、截图和录屏可作本期媒体；其中另一个 `anim` 工程或现成视频不自动获得“动画底稿”的地位。按场记录 `pack / sceneId / 源场景 SHA / 输出帧范围`，完成时对照生成的 `macro_plan.json`，不要用“插入了几段模板”代替“整片按指定模板制作”。

同一包内优先一次 `macro-build`：它已经管理跨场转场、进度、音效及配乐。若有语义需要跨包选场，当前构建器每次仍只接受一个包，需分别构建，再编排总时间轴；还没有一条命令自动生成跨包长片。此时必须保留：

- 每个章节的完整场内阶段和源动作窗；总时间轴以整数帧连续排列，不能拉伸整场动画。
- 章节内口播取帧用章节目标时间；字幕、时间码和全片进度用全局目标时间。第一场标记只属于全片首场，不能让每个子工程都强制呈现开场状态。
- 原模板入场转场要在跨章节边界继续运行。若用 iframe 组合，顶层 `document.images` 看不到内部媒体；需等待当前子页的字体和实际可见图片解码，再截图。
- `S()` 音效加上章节偏移，配乐段落、包络与特殊事件按同一偏移重新合成。直接拼接旧片的混音会带入旧人声或重复音效。
- 最终完整编码的所有帧时间戳、音轨与逐场来源再检查。跨包定制工程不等于公共 skill 已有全自动跨包装配器。

不要把某次成片的私人文字、素材、固定裁切百分比或分镜顺序写成其他用户的默认值。通用修正优先进入构建器，例如依据新口播跟踪人脸；构图仍需按实际素材审查。

## 用户输入与可交付物

用户应提供剪好的新口播视频、完整文案；最好有与最终口播一致的 SRT 或逐词时间。按所选场景提供真实截图、录屏、头像、标识、作品视频、配乐，及账号名称、画幅、字幕语言要求。原作者素材不随公共包分发。只拿文案而没有真人素材时，不能输出冒充真人口播的片段。

Agent 在制作前列出“新台词区间 → 选用宏场景 → 要触发的词 → 所需替代素材”。生成后交付新的可编辑工程与 MP4，并记录输出帧率、帧数、解码与响度、抽帧/连续观看/完整播放的实际范围。剪好的口播总长度按输出帧网格量化后，必须与计划总帧数完全相符，不能通过冻住人脸来补时长。

## 制作步骤

未指定风格、希望比较全部模板时，优先使用[全库选型与构建](automatic-selection.md)的 `auto-plan → auto-build`。单风格仍走原构建器；混合工程保存逐包来源，只有完整独立入场的镜头能跨风格接入，全片口播、字幕、音效保持总时钟。

新制作先走[系统适配规划](adaptive-composition.md)：`macro-plan 显式包@版本 本期brief.json 新规划目录` 生成经过语义、容量、动作窗、接缝和效果变化检查的 spec。brief 的 `anchors.at/frame` 默认是段内相对时刻，生成 spec.cues.at 才是全片绝对秒数。下述 `macro-spec` 为低层人工入口；它不会自动进行语义/接缝规划，不应通过删除 `adaptation` 元数据绕过新计划的错误。已有不含该字段的工程继续兼容。

1. 用 `bash "$PL" doctor` 检查工具，必要时运行 `setup`。阅读所选包的 `README.md`、`manifest.json`，再看源码了解场景的实际进出场。
2. 根据新文案的实际语义与台词时间编写 brief，运行 `macro-plan` 并按报告解决缺项。先按[复用内容核对](adaptive-composition.md#复用前核对实际表达)确认填入的阶段、证据和时间符合台词，再使用生成的 spec。人工历史配方可用 `macro-spec` 认识全部组的接口；cue 默认未绑定，示例文案与原片时长不是本期方案。重复实例使用不同 `id`；相邻输出片段须连续。
3. 为每个实例设置 `durationFrames`、关键 `cues` 和 `slots`。`cues` 的 `at` 是**目标口播的绝对秒数**；若整句 SRT 无法确定句内词时刻，须取得逐词时间或人工标注。画面文案不自动从字幕推断，数字须有本期依据。
4. 处理媒体。`anim4` 的九宫格、软件录屏和作品墙可先用其 `prepare_media.py` 生成序列；图片、视频和序列需要匹配包里定义的尺寸/比例/帧数。作品墙至少需要 27 个真实独立作品，准备器会将其铺成原编舞需要的 389 张展示精灵，`wall-meta.json` 和 `index.json` 保留真实独立数；不能直接把 27 张精灵交给构建器，更不能把重复展示说成 389 件不同作品。`anim4` 的圆形人物卡、`anim3/s06` 的方形人物窗默认在 macOS 用 Vision 从本期口播生成人脸轨迹；其他平台可显式提供经过抽帧审核的固定 `cx/cy/h`，不会悄悄改成中心裁切。构建器对缺失、空值、无效比例及不完整序列会拒绝。长段放映需要足够运动素材，不能用一张静止图冒充新录屏。
5. 用 `macro-build` 编译时间计划并创建新项目。它以整数输出帧绑定新台词，把受保护的动作窗口保持原速；其余**允许停留**的间隙可延长。原真人取帧始终走新口播时钟；动画和原场景 `S()` 音效按源时钟到目标时钟的映射运行。音乐按照原编曲结构在新时间轴重新合成，不直接拉长旧 WAV。
6. 先看首帧、每场关键词的前后帧和连续动画，再检查最长文字、录屏裁切、真人口型、转场、字幕和片尾。修订配置、媒体或场景布局后重新生成，并观看、听取最终编码文件。

`PL` 指仓库的 `scripts/pipeline.sh`，实际命令如下：

```bash
bash "$PL" macro-plan classic-performance@1.0.0 /已有目录/本期brief.json /已有目录/新规划
# 先解决 report.md 的缺项，再使用绑定检查通过的 spec
bash "$PL" macro-build classic-performance@1.0.0 /已有目录/新规划/spec.json /已有目录/剪好口播.mp4 /已有目录/新工程
bash "$PL" stills /已有目录/新工程 0,4,12
bash "$PL" audio /已有目录/新工程
bash "$PL" mix /已有目录/新工程
bash "$PL" render /已有目录/新工程 /已有目录/新片_v1.mp4
bash "$PL" check /已有目录/新片_v1.mp4
```

`macro-build` 可在新工程路径后加 `--subs-js /路径/新字幕.js`。没有字幕输入时工程不会自动凭空生成中英字幕。`macro-spec` 和 `macro-build` 均拒绝覆盖已有目标文件/目录，需使用新路径。直接检查编译出的 `macro_plan.json` 可看到每场源索引、输出帧范围、锚点、绑定和声音事件。若只想预先验证时间与槽，可用 `python3 scripts/adapt_project.py packs/anim3/manifest.json 配置.json --out 新计划.json`；这仍不能代替构建和视觉验收。

3.12.0 起新工程必须显式选择 `"music":{"mode":"track","path":"/路径/本期音乐.mp3","offset":0}`，偏移点按本期重拍选择，剩余音乐必须覆盖全片；缺项保存 needs-binding，不合成旧底乐或偷偷改成静音。只在明确不要背景音乐时设置 `"music":{"mode":"none"}`。旧 source synth 全时长变体已淘汰；构建后固定音乐 SHA、相对素材路径及音效运行代码，`audio` 重验实际文件。背景选择不改变新工程动作 SFX；旧冻结工程不自动升级。使用人脸裁切的场景，其 `faceTracking` 默认 `auto`，需要 macOS Vision/Swift 且失追超过 1 秒会拒绝；`fixed` 需显式给新 720×1280 口播帧归一化的 `cx/cy/h` 并逐镜检查。`anim4` 单色等宽字默认用 macOS 系统字体；其他平台须提供有使用权的 `monoFontFile` 并做字体对照。`subtitlePreset` 默认 `large-en`，也可设 `standard`。`fadeEndSeconds` 默认 0，仅在有意留出无口播收尾时可设 0–2 秒。

### 配置格式

以下是**结构示意**；真实 `cues` ID 和 `slots` ID 由 `macro-spec` 草稿及所选包 `manifest.json` 给出，不能复制示意键名：

```json
{
  "pack": "anim4-showcase-macro",
  "fps": 60,
  "brand": "本期账号",
  "scenes": [
    {
      "id": "开场-01",
      "sceneId": "s01",
      "durationFrames": 528,
      "cues": {
        "title_slam": { "at": 1.2 },
        "wall_handoff": { "at": 6.8 }
      },
      "slots": {
        "text_00": "本期实际画面文案",
        "某媒体槽": "/绝对路径/本期素材"
      }
    }
  ]
}
```

上例没有列全必填槽，因此**不能直接构建**。`durationFrames` 是该实例的输出时长，不是把原片整体按比例拉伸到此长度。数值槽的最小/最大值与 `mustChange` 约束、媒体类型及示例文本的位置都由清单校验。重复同一 `sceneId` 时，各实例的 `id`、`slots`、`cues` 独立填写。

### 片长与动作如何适配

每场源 `motionWindows` 标记了角色、卡片、镜头或视频**真实运动的整个区间**；目标时间里保持约 1×。多个关键词落在同一动作窗时，它们必须与原动作保持相对间隔，不能靠只锁住打击点附近的几帧来掩盖慢放。窗口之外的 hold 才能随新语速拉长。场景较短、关键词过密或目标词位置让动作窗越界时，编译会明确失败。此时选择更短宏场景、拆成两场、改变台词/剪辑节奏或重新创作动作；不能强行线性缩放原工程。

较长新句子可延长已有结果画面的停留、插入相关宏场景，或新写过渡。尽量不让单个静止画面无内容地停很久；`maxHoldFrames` 是包给出的限制。任何自动推算都不能替代对连续动画的观看。

### 两条时钟与声音

- **目标时钟**：真人口型、字幕和新视频的场景边界。口播帧绝不能拿源工程秒数读取。
- **源编舞时钟**：原场景里的 DOM/CSS 状态、镜头、录屏推进与 `S()` 音效触发。每场有分段时间映射，不是全片一个伸缩比例。
- **音乐时间轴**：源音乐章节、音量包络、重拍及特殊音型按所选场景映射，重复场景也会复制相应事件。源编曲按 44.1 kHz 重新合成，最终混音/导出转为 48 kHz；原场景 `S()` 已由运行时收集，不能再把音频清单中的参考音效重复混入。

将原中段场景用作新片开头时，原本提前几帧的入场音效移到第 0 帧，保持声音长度；后续场景仍允许音效提前进入上一场的转场。重新选择和排序音乐章节时，和弦小节也按新顺序合成，不能称与原片每一个采样点或音符相位完全一致。

生成工程内的媒体绑定使用相对路径，并附带该版本的 `audio_runtime/macro_audio.py` 与 `audiolib.py`。以后更新 skill 不会改变旧工程的声音配方；再次合成仍需要 Python、NumPy 和 FFmpeg。系统字体及 Chrome 也属于外部运行环境，尤其 macOS 系统字体不会被擅自复制进工程。跨机器迁移应另验字体、裁切和最终声画。

新素材内容若本身需要按新口播卡点，媒体序列应在准备阶段制作相应片段；时间映射只确保原舞台动画的编排关系，不会自动剪出正确的演示操作。

## 验收门槛

![检查连续动作时看首、中、末帧及接缝](../assets/tutorials/03-continuity.png)

| 项目 | 应检查什么 |
| --- | --- |
| 第一帧与布局 | 真人开场第一帧可见；标题、头像与背景无突跳；所有安全区无裁切 |
| 字体与文本 | 画面字、字幕字号/描边/换行与新文案一致，无演示占位、旧账号、旧数值 |
| 动作与转场 | 每个动作窗连续播放；状态前因后果、场景交接、轨迹与声音落点合理 |
| 媒体与口型 | 录屏和作品墙真实、有可用分辨率；裁切正确；真人口型对齐新声音 |
| 声音与字幕 | 人声、音乐、音效层次可听；字幕时间正确；片尾完整；完整文件解码与帧数匹配 |
| 原工程对照 | 同语义动作按源工程连续比较，记录保留和有意识修改的地方 |

做完这些，才能将某次成片标为已验收。脚本测试、静态抽帧、完整解码各自只证明相应范围；两套包作为公共能力保持 **experimental**，直到新口播的端到端成片和原工程全场对照实际完成并留存记录。验证事实见[验证记录](../docs/validation.md)。

## 下一套工程如何提取

先按[持续模板接入](template-intake.md)接收已完成来源、冻结修订并判断新增价值。相同关系优先增加案例或预设；有价值的新演出提炼为具有独立起止状态的**完整叙事镜头组**。原工程尚未提炼的区间留在来源记录中，不要求每次把整片全部参数化，也不能把只提炼几组称为整条路线已完成。

每个候选保存可运行源编舞、时间范围、语义角色、完整动作保护窗口、文字/数值/媒体输入、精确源码绑定、素材准备与声音规则。实际检查人物进退、对象接力、音效尾音和边界状态后才决定拆分。为新口播制作与源内容不同的实例，检查缺素材、容量和片长冲突的拒绝路径，再逐项对照源工程。新镜头组可用完整短段验证；新增路线另需自己的新内容整片与独立使用检查。确认可停留区与受保护运动，不把长镜头压成静态卡片。
