# 从一套模板适配不同文案

模板的价值是可复用的表达和动作关系。新文案先说明「这段要让观众理解什么」，再选能完整表达它的镜头组。现在增加一层可检查的规划资料：把每个组适合的意图、必须讲完的阶段、固定数量、动作类型、强弱、关键词落点和连接要求写成独立 profile；规划器据此给出选择、淘汰原因和待补输入。

这些 profile 是 `adaptation-experimental`，依据当前源码和清单做过代码核对。它们不改变原包的验收等级：七个已发布风格仍是十七个已验收完整组，03-A 仍是九场候选；新文案、重排接缝和新成片都需要本期声画验收。

## 先组织表达关系，再分段

目标画幅也是本期 brief 的输入。竖屏使用目录 portraitSelection 版本并声明 `"layout":"portrait"`；规划器传递到 spec，构建器冻结布局运行层。语义、固定数量和 cue 不因画幅改变而放宽。标题、证据窗、人物、卡片与连接线的规则见[原生竖屏](portrait.md)，新文案仍须在选定字体和画幅下检查可读性。

不要按每句字幕切一个动画。把连续句子组成一段完整表达，例如：

| 文案的表达关系 | 合适的完整组 | 必须提供的内容 |
| --- | --- | --- |
| 提出主张 → 给出方法 → 分发给三个对象 → 展示实践 → 回应 | 01-A / 01-B 的 `claim-into-container`，01-C / D / E 的 `claim-and-response` | 每个阶段都有本期真实含义；三对象不是装饰数字 |
| 展示材料 → 过程 → 结果 → 三项观察 → 归纳 | 01-A 的 `evidence-focus`，01-C / D / E 的 `evidence-and-focus` | 三段本期素材，三项与结果相关的观察 |
| 概念 → 拆解 → 汇总 → 可复用方法 | 各风格的 `decompose-and-consolidate` | A / B / C / D 固定三部分，E 固定四部分；B 还必须先有真实证据和规则阶段 |
| 表面矛盾 → 实际价值 → 插图解释 → 三步行动 | 02-A 的 `apparent-tension-to-value` | 两个相对立的概念、透明插图、三个可执行步骤 |
| 六类输入 → 聚合 → 网络 → 结论 | 02-B 的 `cards-to-network` | 六类有意义的资料及结论 |
| 七步计划 → 六类能力 → 三项开箱 → 交付 | 02-B 的 `calendar-to-delivery` | 与七、六、三的实际容量一致的内容 |

这些是结构，不是关键词联想。文案出现「方法」二字，并不意味着它包含拆解、归纳和结果；只有两项真实内容，也不能为凑三张卡编出第三项。暂时没有合适组时，规划结果应直接说明缺口，调整段落、选择别组，或者另做一个经过验证的变体。

## 先满足约束，再增加全片变化

规划顺序是：

1. 核对意图和按顺序出现的语义阶段，排除论证关系不合适的组。
2. 核对数量、文字容量、媒体、字体与时长。固定数量不能偷偷补项或删除；时间不够不能加快整场动画。
3. 用本期真实关键词时间绑定 cue。`anchors` 中的 `at` / `frame` 是该段内相对时刻；`phrase` / `line` 从本期有时间的 `transcript` 查找。只有句级字幕时，不能把关键词在句子里的位置估算为精确时码。缺锚点就保留待解决项。
4. 检查前后场连接、同一对象继承、素材身份与音效尾音。
5. 在全部合格的候选之间考虑整片变化：减少连续重复同一组和同类动作，并让强弱有变化。不能为了多一种效果选择不符合文案的组，也不能为了强弱交替打乱原始论证。

每段的 `candidates` 可以为不同完整组提供各自的本期 `inputs` / `slots`；它们是有意设计的候选，而不是把一个字段表强塞给所有动画。规划报告记录采用哪个组、为什么、哪些候选被排除、哪些输入还未解决。

已有计划新增图片或视频时，可使用[当前分镜重新匹配](local-rematch.md)：只改指定段落的明确素材绑定或候选组，保留其它分镜、文案、时长和声音设置。生成建议与采用之间重新核对配置及媒体摘要，避免晚到结果覆盖新操作。

短段没有足够时间完成演出时，正确结果可能是「当前模板无匹配」。长段仅能增加清单允许的停留时间，真实口播仍按最终输出时钟连续播放；受保护动作保持原速。全片结构有变化不等于全片都在动，高强度结论之后的阅读和证据观察同样是节奏的一部分。

## 复用前核对实际表达

规划器核对创作者声明的 intent、phases、counts、anchors 和绑定，不会阅读画面或验证这些声明是否符合真实台词。先写一份简短的本期分镜表，供自己和后续执行者核对：

| 核对项 | 记录什么 | 发现不合时怎么做 |
| --- | --- | --- |
| 表达关系 | 本段原文与真实时间范围；每个必需阶段对应的原句或明确画面解释 | 新闻、个人态度、预告只有部分阶段时换组或调整叙事；不能为填满五阶段杜撰方法、三接收者和证明 |
| 台词与动作 | 关键 phrase、已核实时间、取时依据（逐词数据、整句起点或人工标注）及 cue；场界两侧的台词 | 段落与动作均围绕本期表达安排；不能用源 cue 加场景起点代替观察，也不能移动切点把下一段主题提前数秒 |
| 事实与素材 | 真素材路径、身份、使用区间；历史作品写明版本；图形说明写明“示意” | 合成时间线、装饰曲线和假波形不能标成真实新闻、真实音频或实测结果；旧成片不能称本片自身 |
| 全片节奏 | 每组使用次数、连续重复及理由；人物构图、动作与音乐强弱 | 避免一个完整组只换标题反复填满全片。固定模板只有两个合适组时说明覆盖缺口；在合法候选内增加变化或设计另行核验的桥接，不随机轮换 |

例如，一段讲隐私或作家起诉，给容器改名“新闻证据”却继续显示“镜头／动效／音效”三条合成轨道，接口可能全部通过，但表达关系和证据身份都不成立。同样，片尾仅说更新计划和告别，不必硬塞主张→方法→分发→证明→回应。

重复组的 cue 段内偏移完全一致时，先检查是否沿用了演示节拍；这是复核信号，不是自动判错。原速保护可能限制 cue 的间隔，真实台词若无法满足，应改组选型、合并段落或制作新变体，不能伪造“已精确对齐”。音乐与 SFX 按源动作映射正确，只证明声音跟动作走；仍要连续检查动作是否跟本期台词走。

构建/导出记录用于重现和技术核验。交付时区分抽帧检查、连续运动检查、最终编码试听和全片观看，保存实际做到的范围。固定人脸框的参数是本期脸部中心和高度，不能当通用模板常量；小圆窗在极端姿态也应保留双眼、嘴巴和下巴。自动跟踪目前按整条口播检查失追间隔，原剪辑的黑帧也会触发拒绝；先核对失追区间是否确实无人，不直接把失追当作人物居中，更不能仅为过构建改填任意 fixed 参数。

## 可停留的位置不等于可拆分的位置

`motionWindows` 描述受保护的动作时间。两个窗口之间可能允许多读半秒，但那里不一定具备独立入场、对象状态重建、声音收束或新的真人构图，所以不能自动变成剪点。

当前 26 个完整场景全部标记为 `splitPolicy.mode = atomic`。它的含义是「规划器只能调用整个现有组」，不是说今后永远不能拆。每场记录具体不可拆原因；没有伪造已经可用的小变体。

03-A 有几条必须特别保留的关系：

| 场景 | 当前约束 | 对适配的影响 |
| --- | --- | --- |
| `s02 → s03` | 九宫格中央格放大成 hero，必须连续相邻；`grid_opus55` 与 `opus_hero` 的 `entityId` 声明必须相同，实际来源仍需人工核对 | 不能单独抽出 `s03`，不能换成两个无关作品；两场素材全程 1× |
| `s02` 末尾 | 音乐 riser 在 24.9–25.9 源时间推进到下一场 | 保留蓄势与落点，不在场界截断声音 |
| `s05` | 人物缩窗、软件窗口、功能录屏与结果接管是一次接力 | 软件中段还不是独立动画；细节录屏保留原声明的加速及标识 |
| `s07` | 旧流程条压缩为新时间是同一物体 | 不能只截出压缩动作而去掉它所压缩的旧流程 |
| `s08` | 真人持续在场；101.4 源时间的 chime 尾音跨过画面场界 | 保留人物连续性，混音时让尾音自然延续并检查与下一场的重叠 |

其它原生转场仍保留来源类型，例如闪白、圆形扩展、模糊或擦拭。存在原生转场，只说明源码有这个动作；它不证明任意新相邻场景都能无缝连接。新组合需要检查上一场结束状态、下一场入场以及接缝前后的连续声音。

## 使用示例

公开示例见 [examples/adaptation](../examples/adaptation/README.md)。两份不同文案都使用 `classic-performance@1.0.0`：

- 阳台照料方法：主张、分发与回应 → 三项拆解归档。
- 会议证据复盘：三段证据与三项聚焦 → 三项拆解归档。

同一模板因为表达关系不同，选择不同完整组；第二份也给归纳段更长的阅读空间。第三份只有两秒、要求五项、没有收束，用来展示为什么必须拒绝硬套。

运行规划：

```bash
bash scripts/pipeline.sh macro-plan classic-performance@1.0.0 \
  examples/adaptation/01-method-introduction.brief.json \
  /路径/本期工程/方法介绍规划
```

输出目录必须尚不存在；包含 `spec.json`、`report.json` 和便于阅读的 `report.md`。`needs-binding` 表示已找到完整组组合但仍缺输入，`blocked` 表示没有可行组合，只有 `ready: true` 才能进入后续构建校验。

命令还保存本次 `profile.json`。退出码 0 表示可进入构建前检查，2 表示诊断草稿已保存，1 表示输入格式或规则无效。人物口播是在 `macro-build` 才导入，因此规划报告会单独列出 `deferred`，不会伪造已导入成功；导入后必须检查真实帧、talkmap 和全片时长。字体、所选音乐、人脸裁切及最终画幅继续按构建器要求检查。

示例全部新写，并明确为内容示意。没有附真实口播、证据视频或关键词时间，`anchors` 留空，所需视频为 `null`。它们展示规划与诊断，不是可以直接制作的素材包；前两份报告为 `needs-binding`、第三份为 `blocked`，都应是 `ready: false`；这些状态是预期行为。不要把原包的演示文字、演示路径或源 cue 时码填回这些缺项。

## 从提炼新模板时增加能力

新模板入库时，一起交付「能力矩阵 + 连接合同 + 验证片」。至少记录：

| 能力 | 提炼时要回答的问题 | 可以扩大适配范围的交付 |
| --- | --- | --- |
| 语义 | 这个动作说明的是对比、递进、因果、聚合还是反转？哪些阶段不能少？ | 必选和可选阶段，以及每阶段真实例句 |
| 数量和字数 | 两项、三项、五项是否真的能运行？长标题如何布局？ | 明确数量变体；长短文本版式与可读性验证 |
| 时间 | 哪段只能原速？哪里能停留？最短和最长各是多少？ | 短、中、长三种实际演出，保留动作保护区 |
| 拆分 | 独立开始时如何恢复物件、人物、相机、媒体和音轨？ | 真正可调用的子组源代码、入/出场状态及测试 |
| 连接 | 哪些前后组合可以硬切、匹配剪辑或使用独立转场？ | 具体相邻组合的连续声画样片；共享实体必须可追踪 |
| 媒体 | 无图、静态图、真实视频是否分别成立？ | 经验证的无图/图/视频变体，不能使用假证据替代 |
| 声音 | 起音绑定哪个动作？声音持续多久？尾音能否跨界？ | 可重编的事件、音乐强弱区、尾音与重叠规则 |
| 全片变化 | 同意图是否有不同动作家族与强弱选择？ | 有语义对应关系的候选变体，支持全片选择而非随机换效果 |
| 验收 | 换主题、数量、时长、横竖屏之后是否仍成立？ | 不同内容的新片、最长文字、接缝连续检查和作者反馈 |

将这些变体写入新版本，分别绑定源码 SHA 和验收范围。旧冻结包保持原字节；不能修改旧清单就宣布旧演出具备新的拆分能力。

## 当前实现边界

- 现有冻结包使用外部 sidecar，绑定精确包 ID、版本、规范化 manifest 摘要和各场源码 SHA；新提炼包将同一合同嵌入 manifest 后再绑定完整摘要。已有源码 SHA 不会在加载时自动改写。详见[提炼入口](template-intake.md)。
- 现在规划和诊断现有完整组，复用原有构建器的时间、文字、媒体和 cue 校验；没有自动创建新动画、把固定三项改为任意数量，或自动生成已验收的组内剪点。
- 效果家族和强弱用于规划偏好；人类声画验收、素材真实性以及文案的真实语义仍需要本期核对。机器能检查已标注阶段的顺序，不能证明一句话里的论证本身真实完整。
- 新成片仍走 `macro-build → 抽帧与连续声画检查 → audio / mix / render / check`。规划通过不等于成片通过。

构建保存 `adaptation_profile.json`、重新校验的 `adaptation_report.json` 和版本摘要。`audio_boundary_report.json` 在构建时明确只有部分清单事件；执行 `audio` 后以实际采集的全部 `S()` 更新，列出跨场尾音、提前起音、密集重音、未知时长及潜在结尾截断。时长估计不是听感缺陷结论，报告不会自动删音效或改混音。原生连续场的正常尾音接力标为提示。测试范围见[适配机制验证记录](../docs/adaptation-validation-2026-10-03.md)。
