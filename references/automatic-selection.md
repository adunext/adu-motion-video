# 全库选型与长短素材适配

3.10.0 增加 `auto-capabilities → auto-plan → auto-build`。当前目录的 10 种风格、32 个完整镜头组参与比较，横竖屏都使用对应的显式候选版本。源模板的发布等级保持不变；全库组合本身为 experimental。

用户只需要给口播、文案、素材和画幅。下述结构化输入由执行助手整理；不要要求用户为每套模板手填一份 JSON。

## 助手先理解整段表达

1. 阅读整篇文案和真实口播时间轴，标出主张、方法、证据、比较、拆解、聚合、交付、反馈等完整表达关系。按因果段落组织场景，不按字幕句数随机换动画。
2. 执行 `auto-capabilities`，查看每组的意图、阶段、数量、槽位、文字容量、动作窗、落点、接缝与字体要求。它不加载源演示文字作为新片文案。
3. 给有实际内容依据的候选填入短标题、完整阶段、真实素材和准确 cue。不同模板可以使用不同的简短表达，但不能增加台词没有的事实、对象或结果。机器只能校验这些声明，助手须核对其忠实性；这里没有关键词分类器或另一个模型 API。
4. 长段超过单组容量时，依据真实台词提出其他完整分段 `segmentations`，每条路线总帧数必须一致。不能把同一段复制三遍，不能用源演示 cue 假装新口播时码。只有句级时间且需要句内动作时，先获得实际词时码。
5. 执行 `auto-plan` 并读报告。缺媒体或短句超容量时，助手修改合法候选并再次规划，最多先尝试三轮；仍缺真实输入时列出具体缺口。调整显示短句不改变口播观点。不要删 `adaptation` 或改 `ready` 来跳过校验。

## 命令与格式

```bash
bash "$PL" auto-capabilities > /已有目录/能力.json
bash "$PL" auto-plan /已有目录/本期auto-brief.json /已有目录/新全库规划
bash "$PL" auto-build /已有目录/新全库规划/auto_plan.json /已有目录/剪好口播.mp4 /已有目录/新工程 --subs-js /已有目录/字幕.js
bash "$PL" audio /已有目录/新工程
bash "$PL" mix /已有目录/新工程
bash "$PL" render /已有目录/新工程 /已有目录/新片_v1.mp4
bash "$PL" check /已有目录/新片_v1.mp4
```

输入 `schema="adu-auto-brief/1"`，其余段落字段沿用 [macro brief](adaptive-composition.md)。区别如下：

| 字段 | 用法 |
| --- | --- |
| `candidates` | 键为能力表中的完整 ID，例如 `01-A:decompose-and-consolidate`，值为本期 `inputs` / `slots`。不要把一个字段表强塞给全部风格。 |
| `candidateInterpretations` | 可选，按同样 ID 填候选自己的 `intent/phases/counts/anchors/energy`；段落 ID、原口播文本和时长保持。选中的解释会保存并重新校验。 |
| `allowedStyles` | 可选风格范围，例如 `['01-A','01-C']`。用户锁定 `01-B` 时只能填 `['01-B']`，缺能力时不能偷偷换风格。 |
| `stylePolicy` | 默认 `coherent-first`，优先整片统一风格；单一风格覆盖不了且混合路线完整可用时才组合。`mixed` 可直接在合法组合中优化变化，仍有风格切换成本。 |
| `segmentations` | 可选的 1–16 条完整路线，每条 `{id,segments}`。总帧数一致；语义分段由助手据真实台词决定。 |
| `styleSettings` | 按风格设置 `externalFontFiles` / `monoFontFile`，避免不同来源同名字体槽冲突；其他设置沿用全片顶层。 |
| `narrationDuration` | 剪好口播的实际视频时长，按 60fps 网格量化后须等于分镜总帧数。 |

`auto-plan` 保存完整比较报告、选中的路线、可构建的分组 spec 和 source/profile 指纹。退出码 0 是导入前绑定检查通过，2 是待补/受阻草稿，1 是无效输入。部分字体没有随包分发，缺字体不会被报告成 ready。

## 选择和重复处理

先满足语义、数量、文字、实际媒体区间、完整动作窗和前后场依赖，再优化风格统一与变化。候选缺素材时，无论影片多长，都不能靠增加重复惩罚让它胜过完整可用的路线。依赖同一物件续接的两组必须保持实体身份；跨风格入口必须有独立入场合同，不把原片中的形变接缝移给无关模板。

`report.rhythm` 仍会列出连续重复、固定两三组循环、同类动作连用和过长停留。合法选型可以减少相邻重复，但“ABABAB”也可能单调，因此还须检查全片表达与节奏。没有真正不同且适配的候选时，保留必要重复或制作经过验收的新变体。

## 构建时保持连续声画

单一风格沿用原构建器。混合工程把连续使用同一包的镜头合并为子工程，各包独立运行自己的布局和编舞；根工程用整数帧驱动它们，风格间使用明确切镜，不插入未经验证的形变桥接。

口播只导入一次，沿用 HDR → sRGB 处理并保存源色彩证据。子工程取母版的准确帧区间和 48kHz PCM 样本，根工程声音始终用未变速、未重切的完整母版。字幕数据保留完整时间轴，子工程按全局口播时间显示。可见图片须完成解码，切换子工程后等待同一帧绘制；重复的零缩放归一化，跨模板导出采用软件绘制，往返跳转不会使用上一帧代替。

动作音效只映射起音点，保留生成器 `d`、前奏和跨包尾音，最终在全片时钟合成。自有配乐按全片统一使用；默认源配乐保留每包的乐器和配方，风格边界做 120ms 音量坡道，片长不变。这是新的组合混音策略，需要连续试听，不能称为原曲无缝继承。带风险的 HDR/DV/缺标签素材仍需要实际色彩对照记录。

工程再次核对本期 brief、所选 spec、源版本、素材和字体；旧建议不能覆盖改过的输入。新文件保存到新目录，旧模板包与既有视频保持原字节。

## 验证范围

见 [3.10 全库测试](../docs/template-auto-selection-3.10.md)。自动规划不证明表达标注忠实，也不替代真实人物裁切、长标题排版、完整影片观看与试听。候选不会因本次机器测试被提升为 stable。
