## 共享引擎

```text
index.html + style.css     舞台、字体和组件样式
lib.js                    图层、缓动、逐词动画、Scene、SFX、素材帧加载
scenes.js                 本条视频的分镜、布局、画面与音效时间点
main.js                   renderAt(t)、镜头、转场、READY
render.mjs                浏览器截图 -> FFmpeg -> 无声视频
audio.py + sfx.json        合成配乐/音效，随后与口播混音
assets / talk / sc        图像与媒体帧素材
```

这不是 AE、剪映、Remotion 或 HyperFrames 原生工程。主要画面是 DOM/CSS transform/filter 和 SVG；真人/视频常以 JPEG 帧序列嵌入。浏览器负责渲染，不负责自动发明内容。

`renderAt(t)` 是共享接口。原 `Scene(s,e,bg,opt)` 注册全局时间区间；`mk/place/show/words/wordsAt` 创建并更新图层；`sc.update(t)` 接收**全片绝对秒数**。旧 `adu-video-studio/assets/starter` 则向 `scene.update` 传**场景局部秒数**，移植组件时注意转换。

原文件按行比较，lib/main 高度相似，scenes 差异很大。可复用的是运行时、视觉表达方式、资源与音效方法；每期分镜需要重新设计。

## anim3 的叙事组件

- 0–3.3：钩子标题、实拍卡片。
- 3.3–11.9：年代数字、CRT、Win95 弹窗、加载条。
- 11.9–20.67：痛点卡、百分比/次数/小时计数。
- 20.67–28.37：手写揭示、设备时间线、账户卡。
- 28.37–36.8：通知消散、App Dock、专注大字。
- 36.8–44.53：中心人物与节点、Bezier 流动、进度冻结。
- 44.53–55.67：发布时间线、双赛道对比。
- 55.67–59.9：内存横条对比。
- 59.9–63：终端逐字演示。
- 63–69.6：作品卡、天平、指标、鹦鹉反应。
- 69.6–73.25：打勾总结。
- 73.25–82：评论、盖章、片尾；导出受 END 限制。

`script.srt` 有 60 条字幕，但运行时**不读取该文件**。大字及出现时间写在 `scenes.js`。`edl.json`/`segs.json`/`align_pts.json` 是对齐过程资料，不是当前直接生效的场景清单。

`build_sync.py` 从三条原 MOV 按七段 `sync_segs.json`、1.1 倍速重建口播。源时间计算含 `ast` 音轨偏移与 `fix`；它们只适用于该次剪辑。`fix` 模式会覆写同步参数。原同步临时 PCM 文件不随包提供，不能不加检查直接运行。

历史源码 END、底轨、mix.wav 和最终片尾时长略有差异；按任务选择帧数基准和收尾策略，不要默认互相完全一致。

- 0–8.8：大字、真人卡片变圆、作品墙。
- 8.8–25.9：九模型九宫格、逐项高亮、Token 计数。
- 25.9–40.4：成片放大、总结、审片报告、上一条作品。
- 40.4–52.7：全品类、作品墙、镜头语言与叙事节奏。
- 52.7–69.4：人物情绪、软件录屏、AI 匹配、模板。
- 69.4–78.1：赛道、账号卡。
- 78.1–89.7：时间压缩、工作与编程画面。
- 89.7–102.92：行动与互动结尾。
- 102.92–108.4：制作说明/提示词展示。

`talkmap.js` 映射输出帧到口播来源目录与帧号；`face.js` 提供脸部中心/高度，用于圆形或缩小卡片的裁切；`wall.js` 索引作品墙，4×4 精灵图按时间切换。`subs.js` 有 39 组双语字幕，逐字高亮在 `scenes.js` 中实现。

`vert.html` 是单独的竖屏包装：动画面板、真人和字幕重新组合；不是横片改编码尺寸就能得到的布局。

已知状态问题：S1 原版 `cam._sm` 在 `camAt` 后赋值，会依赖前一帧；S2 高亮使用 `cssText +=`，倒退时未恢复。`codex_demo` 仅修了自身 S1 副本，不能声称原工程全部修复。

## 使用旧工程的注意点

- anim3 的旧 renderer 导入历史临时目录中的 Playwright，公开包不保留该本机依赖；两套旧 renderer 都绑定特定 Chromium 缓存版本。使用 skill 的导出助手，或明确修正新版本副本。
- anim4 的历史混音脚本依赖临时 voice.wav；当前机器不一定拥有它。素材来源和声音需要放在持久项目目录。
- 旧 `render_all.sh` 清理分段文件并覆盖既定输出；旧 renderer 对加载/编码失败的处理不严格。不要直接运行它们覆写用户工程。
- 原 `imgWait()` 把图片 onerror 也当作完成；必须另查缺图。作品墙是 CSS 背景图，不能仅检查 `<img>`。
- 系统字体与本地 fonts 目录不是同一回事；旧页面实际使用 PingFang/SF 等系统字体，目录存在不代表已加载。不要把系统字体文件重新打包分发。
- `gen_images.py` 是生成外部素材的历史脚本，不是动画引擎；可能有凭据与代理配置，不复制进 skill，不自动调用。
- 历史完整修改和导出只证明对应工程可编辑，不证明新题材自动拥有完整模板。
