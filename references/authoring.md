# 新文案、镜头与声音

## 从输入确定交付

| 输入 | 可以直接推进 | 需要补齐的部分 |
|---|---|---|
| 新文案 + 新真人口播 + 素材 | 素材导入、字幕整理、分镜、真人包装、配乐音效、成片 | 若时间轴有剪辑，先重建音画一致的口播底轨 |
| 新文案 + 旁白录音 | 以实际录音分句定时，制作无真人出镜的解释视频 | 可选配图、屏录或已有角色素材 |
| 只有新文案 | 故事结构、镜头设计、标注为无配音的动态预览 | 有声交付需要用户录音或明确的合成声音选择 |
| 旧工程 + 局部改动 | 保留节奏，修改对应图层并导出独立版本 | 若改语义或时长，核对旁白、字幕及所有时序 |

Skill 不内置自动转写或配音。缺少 SRT 时可按用户文案整理分组；需要自动识别语音时说明所用外部工具。

若用户说“照这个风格”，复用排版、运动与配色的规律，重新为语义选择画面。不要自动套用旧片的每个镜头、数字、产品判断或旧年份。

## 把文案变成可看的故事

先写一张紧凑的分镜表：`场景 / 旁白范围 / 画面要表达的一个重点 / 视觉动作 / 素材来源 / 起止秒`。不需要为每个场景额外征求确认；已有充分授权就连续推进。

可用于不同题材的表达方法：

- **开场主张**：一句短标题与一个明确视觉动作。字幕承载逐字口播，大标题只提炼观点。
- **具体证据**：屏录、实际文件、对比视频、人物示范，证据卡进入后留足可读时间；示意 UI 要与真实实测区分。
- **比较**：并排卡片、九宫格、同量纲数值、由总览推到关键细节。不要伪造测试结果填满设计。
- **经历/代价**：年代、进度、出错界面、时间压缩、物品更换，用画面代替一段抽象形容词。
- **转折**：让构图、背景或运动方向改变一次，配合语言中的转折；不在每一句间都堆转场。
- **结尾**：回收开场问题、给出明确行动或一句结论。最终字卡需要停留后再淡出。

一条视频不必包含以上全部结构。画面的复杂度服务内容；保留静止与留白，让最关键的运动有对比。

## 时间与媒体

确定的旁白是主时钟。先读实际媒体 duration，再用词/句时间戳布置文字和音效。只有预计字数时，时间表必须标记为估算，不能称为已完成口型同步。

原引擎通过图片序列确定性显示视频，和视频元素实时播放不同：

```text
输出帧 f -> 时间 t=f/fps -> 场景局部时间 t-start
       -> 口播剪辑映射 -> 来源视频和来源帧
       -> 同时刻的字幕、脸部裁切、其它素材帧
```

可用 FFmpeg 从用户选定视频生成有界的帧序列。只抽需要的区间/尺寸，保留源路径、源帧率、起点、速度和文件命名规则。不同素材可以有不同原始帧率；输出 60 fps 不等于所有素材也有 60 个独立帧。

引入视频元素时必须显式 seek 到时间并等待 `seeked`/已解码帧再截图，不能让 `autoplay` 决定画面。当前严格渲染助手不提供这条管线；需要时实现并验证。

若更换人物口播，重新制作底轨、帧映射与脸部参数；旧映射只对应旧素材。仅有新配音不能使旧真人视频自动说出新台词，可改用无口型的插画/素材画面或使用另外授权的口型工具。

音效 cue 和画面同源记录；关键音效跟随字幕关键词/物件出现，音乐为旁白让出空间。文件声轨、`mix.wav` 和 `audio.py` 的合成配乐是不同东西，不能只改 `SFX` 就认为已经改好音频。改时序后要重新导出 cue 并混音。

## 布局与确定性

新片先确定横/竖屏。为人物、主要证据和字幕分别留空间；窄屏重新编排层级而非等比例压缩所有内容。

长中文、英文换行、品牌名和中英文字幕分别检查。自动缩小只解决有限长度，必要时编辑显示文案、拆页或更换布局，不能无限缩小到不可读。

所有可见状态应是 `f(t)`：位置、透明度、滤镜、圆角、裁切、文本高亮都需要在每次渲染设置。检查同一时间在正向、倒退和独立加载后是否一致。初始化必须等待字体、图片和 CSS 背景图。

## 扩展顺序

每次只把已经在实际新片里有用的内容沉淀为组件：标题节奏、对比卡片、媒体窗、字幕、人物布局、作品墙、图表或转场。新组件记录参数、资源依赖、时间语义、横竖屏约束和一个可渲染示例。

本 skill 已包含口播对齐、字幕生成和音频预处理工具。新题材仍需要分镜与布局适配；它不是全自动数字人系统。
