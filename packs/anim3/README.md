# 编辑卡片连续叙事：完整场景包

这个包保存了源工程的 **12 个完整 DOM 场景**：每段里的画面对象、进出场、镜头位移、遮罩、数字变化、角色动作、跨阶段状态和 `S()` 音效调用都在 [`scenes.js`](scenes.js)。它不是从原片截出的 12 张卡片，也不是 9 个基础 `TPL` 的别名。`manifest.json` 为每段列出了原时间、原速动作窗、文字／数值／媒体槽；`audio_timeline.json` 记录了配乐章节和特殊音乐事件。原工程与模板的逐项差异见 [`SOURCE_AUDIT.md`](SOURCE_AUDIT.md)。

## 文件与依赖

| 文件 | 用途 |
| --- | --- |
| `scenes.js` | 12 个顶层 `(() => { … })();` 场景块，按 `new Scene` 顺序对应 `s01`–`s12`；原有多阶段动作和 SFX 仍在里面 |
| `lib.js`, `style.css`, `index.html` | 与场景兼容的 DOM 助手、样式和浏览器入口；字体只使用系统字体 |
| `main-source.js` | 原工程转场／镜头调度的源码快照，供核对；套用新文案时由通用 `macro_main.js` 按计划驱动 |
| `audio-source.py` | 原编曲及音效实现的源码快照；原配乐按 44.1 kHz 重合成，最终混音／导出走 48 kHz |
| `manifest.json` | 场景、动作锚点、可替换槽与源素材形态 |
| `audio_timeline.json` | 原配乐段落、重拍、上升音、停机与片尾音事件，供新时间线重映 |

公共仓库不附带原人物、鸟、设备图、真人口播和配乐。每个被选中场景的 `image_*` 槽都必须由用户提供可用图片；带真人卡的场景还需要完整口播素材、`talkmap.js` 和 `talk/` 帧。缺素材时应阻止正式导出，不可把空白头像或错误路径当成成片。

原透明 PNG 的外形比例仅用于选素材，不要求复制原角色：设备图约 1.48:1，CRT 约 1.08:1，半身人物约 0.47–0.71:1，飞鸟约 1:1，片尾人物约 0.63:1。替换素材应保留透明背景并沿用画面底部锚点；若比例相差明显，按抽帧结果调整该对象的位置和高度。真人卡使用竖向口播画面；口型按新成片时间读取，绝不拿源场景时间去取真人帧。

## 给新文案套用

1. 先按语义挑一个或多个完整场景，而不是逐句选静态卡片。`role` 说明场景包含哪些连续动作；例如 `s05` 是“通知围绕人物 → 溶解 → 角色卡 → 软件坞 → 蓝色圆形转折”，这是一个场景的五段演出。
2. 从新 SRT／口播时间给 `cues` 指定触发词，生成 **整数输出帧**。`motionWindows` 覆盖原有的完整动作起止区间，这些时间窗保持源动画 **1× 速度**；只有窗间停留区可以伸缩。语义词若挤不进动作窗，适配器会拒绝并要求延长镜头或改选场景。s06 的联网流动和 s09 的终端敲字是连续演出，整场不可压缩或拉长。
3. 为选中场景填写所有 `required` 槽。每个文字槽的 `sourceSpans` 指向原 IIFE 块中唯一审核过的位置，`sourceBlockSha256` 防止源码变化后误改同名短词；不再以全场字符串搜索替换。`renderContext=html` 的值先做 HTML 转义，再做 JS 字符串转义；`text` 只做 JS 转义。显式示例和占位词以及演示数值带 `mustChange`，不能原样进入新片。
4. `number` 槽通过 `window.PACK_NUMBERS[binding]` 注入新数据。s02 起止年份都是四位整数（1000–9999），整段年份在原窗口内滚动；进度条的长度与百分比同源；s03 重装计数到达绑定的总次数；s08 两个容量共用一个单位，柱长由两项实际数值自动计算；s12 点赞计数最终显示绑定值。对于同一个源场景在新片中重复出现的情况，每个实例分别绑定自己的文案、数字、媒体和动作锚点。
5. 每帧先由目标帧得到 `outputT`，再用本段固定动作窗及窗间停留点求 `sourceT`，设 `window.PACK_OUTPUT_TIME=outputT` 后调用原 `sc.update(sourceT)` 和 `sc.cam(sourceT)`。`scenes.js` 的 `camAt` 用 `PACK_OUTPUT_TIME` 取新口播帧，保持口型正确。转场采用相邻场景的新边界；原 `SFX` 点和声效持续时间端点也通过同一映射搬到输出帧。
6. 配乐事件从 `audio_timeline.json` 按同一映射重排；如果用户提供自己的曲子，用新片段落重新对齐重拍，不把原音频文件硬贴到新时长。字幕始终取新口播时钟。
7. 抽取每个锚点前后 `n−1,n,n+1` 帧，以及每段中点、最长文案帧和相邻场景接缝；检查文字安全区、素材比例、动作顺序与音效。s07 的六个时间轴刻度与“晚了 X 个月”是独立可替换文字，必须人工核对实际日期差；不能因字段齐全就当成事实已验证。再导出全片并听完整段混音。

新句子比源段长时，优先给人物／结果画面增加停留，再根据语义插入另一个完整场景；不能把所有动作等比例慢放到失去节奏。新句子更短时，可选更紧凑的场景或重新组织场景，动作窗本身绝不压缩。某段文字超过 `maxChars`，先重写字幕外的画面文案，再局部改排版，不靠全局压小字号。s01 的结论标题还有实测宽度守卫：进入真人卡区域或需要把 190px 重点字缩小超过 10% 时直接报错。

## 场景与真实动作

| 场景 | 编舞跨度 | 复用场合 |
| --- | --- | --- |
| s01 提问开场 | 两层标题逐词入场、重点重击、人物卡弹入、道具反弹 | 观点开头 |
| s02 旧环境与错误 | 数字滚动、旧设备、七个弹窗连爆、技能卡和进度条 | 痛点与历史 |
| s03 痛点计数 | 三组记忆词、三张信息卡、加载条、故障抖动与累计数字 | 多痛点证据 |
| s04 迁移时间线 | 书写式遮罩入场、四设备、账户卡跳跃、飞行角色 | 历程与变化 |
| s05 注意力转折 | 环绕通知、消散、六张角色卡、应用坞、圆形蓝屏 | 从干扰到洞察 |
| s06 指挥网络 | 中心人物、六节点联线、沿线流动数据点、停机灰化 | 系统关系 |
| s07 时间差与赛道 | 版本间距、惊讶反转、双赛道终局 | 先后与机会 |
| s08 容量对比 | 弱点道具、反转文字、双进度条和解释 | 双指标知识点 |
| s09 终端演示 | 终端逐行打字、工具切换、角色弹入 | 软件步骤 |
| s10 创作反馈 | 六作品卡、天平倾斜、三数字卡、飞鸟表演 | 产出与收获 |
| s11 结论清单 | 四卡逐个入场并勾选，最终大字砸屏 | 总结与号召 |
| s12 评论与名片 | 评论滑入、误区划线盖章、整屏结尾名片 | 互动和片尾 |

音频 `S()` 事件全部由原场景代码生成，包含错误弹窗、磁盘、通知、数据包、重击、划线、盖章、飞鸟等音型。历史编曲的 8-bit 桥段、停机降能、重拍、上升音和片尾和弦在 `audio_timeline.json` 另行列出。`audio-source.py` 只是源结构记录；新口播长度和转折点确定后再构造新编曲。

## 新人物的裁切（rc.2）

`s06` 的方形人物窗根据新口播的人脸轨迹取景，清单标记 `requiresFaceTracking:true`。选择这一场时，构建器默认使用 macOS Vision；无法使用时须提供明确的 `faceTracking:{mode:"fixed",cx,cy,h}` 并查看实际取景，不能退回旧片的固定顶部裁切。其他竖长人物卡保持原构图，不额外要求跟踪。
