# anim4 源工程到公开宏场景包的核对

## 取材与保真边界

原工程是用户提供的本地 `Claude Opus 5.5/anim4`：`scenes.js` 有 9 个连续 Scene，时长 108.40 秒，1920×1080、60fps。公开包以仓库已有的 `examples/showcase-scenes.js` 为场景底稿；该底稿与原工程同为 754 行、9 个 Scene、118 处源码 `S(...)` 调用，原来的动作时间、转场、镜头、九宫格、双作品墙、人物缩窗、审片、软件窗口、赛道、账号卡和片尾打字的结构仍在。循环与数组展开后，`sfx.json` 是 175 个实际音效事件。

包内 `scenes.js` 保留整个场景 IIFE，不把场景改写成静态卡片。与公开底稿相比有几项有意差异：人物标签改为 `PACK_PRESENTER_LABEL`；S1 裁切在 `camAt()` 前从当前时间赋值；S2 高亮属性每帧确定赋值，避免反复或倒序取帧积累 CSS；S8 尾卡层级每帧重设；S6 账号卡初始数字归零，真实值只由本期必填数值槽驱动，若将 S6 选为新片首场，人物首帧直接可见，非首场仍按原渐入动作；S6 第四数值以 `String(值)` 显示，避免原本应为整数的年份出现 `.0`；S4 原 GitHub 标记改为必填的 `wall_badge_icon`，来源不是 GitHub 时不会误用其标志；作品墙的显示计数来自独立作品数，而非补齐画面的格子数。这些变动不移除原场景编舞和音效触发。

文字与数字通过 `manifest.json` 中每个 Scene 的 `sourceBlockSha256` 和槽级 `sourceSpans` 绑定到准确的源码字符区间。短词 `6`、`low`、`有`、`制作` 不能以全文查找替换；动态的 medium/high/Ultra、三种镜头术语、审片结果、九宫格第五格名称都有独立槽。演示方案、示例品牌、假数据说明与旧结尾提示词标记 `mustChange`。所有数值计数槽必填且绑定整条表达式，使新数值继续沿原来的计数曲线运动。

## 素材、时间与音频

公开仓库不含原口播、肖像、软件录屏、九路作品视频、389 张作品墙精灵、私有配乐或第三方作品。`assetDefinitions` 声明原序列帧数、帧率、参考尺寸与画幅；`prepare_media.py` 只接受使用者提供的本地合法素材并在新目录生成相同帧序列。作品墙至少要 27 个独立作品，布局仍生成 389 个格子；不足 389 时循环排布，`wall-meta.json` 的 `uniqueWorks` 和画面计数是真正的独立作品数，不能宣称格子数是作品数。第 4 场的来源图标也须由使用者提供。

口播画面按新视频输出时钟取帧；场景动作、镜头、帧序列与音效按原 Scene 时间映射。`manifest.json` 列了 66 个语义节点与 42 个动作保护窗。S2 的九路视频和 S3 放大的作品视频从头到尾持续播放，因而这两场 **整场锁定原速 1×**；新台词若容不下应拆分、增加场景或另写镜头，而不能靠拖慢视频凑时长。其他场景保护人物缩窗、作品墙波纹、录屏、转场等连续动作，允许在安全间隙调整持留。不能把新口播的时长直接乘到源 `t` 上。

`audio_timeline.json` 单独记录了 21 段音乐编曲、66 个音量包络键、175 个音效事件及特殊低频/过门/片尾处理。原曲目的权利与音频文件没有转给本包；新成片应以本期有权使用的音乐和这些编排信息重做混音，不能把原 108.4 秒音轨简单拉伸或把 175 个点压成少数通用音效。

## 已核对与未证明的范围

- 静态核对：原工程、公开底稿、包各为 9 个 Scene；包有 175 个音效事件。场景源码通过 JavaScript 语法检查，`sourceBlockSha256` 与全部文字/动态/数字跨度可校验，媒体预处理曾以本地测试视频生成所需尺寸、帧数的序列。
- `index.html`、`lib.js`、`main.js` 和 `style.css` 保存 HTML 动效工程的源结构；原页面的内联组件样式已补入 `style.css`，供新构建入口复用。完整新片须使用新 `talkmap.js`、`wall.js`、`subs.js` 和用户素材。当前 builder 在 macOS 上默认用系统 Vision 生成人脸跟踪；手动指定固定裁切时须检查圆形人物窗是否居中。
- 本文件记录的是源码与接口层面的保真，不把静态核对冒称为每一种新文案、新长度、新媒体组合都通过了全片人工审片。每次实例化仍须检查首帧、跨场过渡、字幕、最长文字、人物口型、动态数字、音效位置和片尾。
